## 5. Cutoff analysis (candidate: end of week 4 → `day < 28`)

We represent the cutoff as **day 28, exclusive** (days ≤ 27 are observable, including pre-course days
< 0). "Week" is derived as `floor(day/7)+1`.

| Quantity | Value |
|---|---:|
| Enrolments unregistered **before** day 28 | 5,040 (15.5%). 3,097 of these unregistered on/before day 0 |
| Enrolments registered on/after day 28 | 18 |
| Missing registration date | 45 (39 Withdrawn, all with an unregistration date) |
| Still registered at the cutoff | 27,553 |
| **Prediction population** (registered by day 27, not unregistered before day 28) | **27,535** |
| … with ≥1 VLE interaction before day 28 | 26,595. 940 have none (563 of those end in Fail) |
| Enrolments with ≥1 non-banked submission before day 28 | 20,185 |
| Module-presentations with ≥1 assessment due before day 28 | 16 / 22 |

The first assessment deadline varies by module. It is day 12–25 for AAA, BBB, CCC, DDD and FFF, **day 33 for
EEE** and **day 61 for GGG**. GGG's TMAs/CMAs also have weight 0 (only the exam counts).
Sensitivity: 11 module-presentations have an assessment due by week 3, 16 by week 4 and 19 by week 5/6/8.
Going beyond week 5 does not add any module-presentations with assessments. It only delays the prediction.

Population at the cutoff: Pass 12,356 · Fail 7,037 · Withdrawn 5,119 · Distinction 3,023. The median
unregistration day of the remaining Withdrawn students is 109, and the minimum is 28.

## 6. Methodological issues and proposed decisions

### 6.1 Withdrawals before the cutoff (label leakage/triviality). **Decision: exclude**
5,040 enrolments are already withdrawn before day 28, so their label is known at prediction time. Keeping
them would inflate performance on the Withdrawn class. They leave the prediction population, and
the 18 late registrations do too. Final N = 27,535.

### 6.2 When is an assessment score "available"? **Cannot be established from the data**
OULAD stores the submission day, **not the day the mark was released**. CMAs are computer-marked, so the mark is plausibly
immediate. TMAs are tutor-marked, and the marking delay is unknown. Proposed handling:
- **Main model:** we use a score only if `date_submitted < 28` (assumption: the mark is available at
  submission). This is common practice with OULAD, but it is an **assumption**, and we state it as one.
- **Sensitivity model:** the same model without any score features (behaviour + submissions only). This
  shows how much performance depends on that assumption.
- 2,622 pre-cutoff submissions are for assessments with a deadline **after** the cutoff (early submissions).
  They are valid observed events, and we keep them.

### 6.3 Structural missingness of assessment features
In EEE and GGG (6 module-presentations) no assessment is due before day 28. For these students
"no submission" does **not** mean non-submission. Features will separate *not applicable*
(`n_assessments_due = 0`, `submission_rate = NaN`) from *0%*. The evidence store must express this
explicitly ("no assessment was due before the cutoff"). This matters directly for the LLM grounding
evaluation.

### 6.4 Train/test split. **Proposed: temporal, by presentation**
- **Train:** 2013B, 2013J, 2014B (18,321 enrolments). **Test:** 2014J (9,214 enrolments).
- All 7 modules appear in both train and test. The alternative, 2013 → 2014, would leave CCC unseen in training.
- Caveat: 2014B (Feb start, 241 days) ends at about the time 2014J (Oct) starts. Train outcomes are
  therefore only approximately "in the past". We state this as an approximation.
- 1,259 students have enrolments in both train and test (different enrolments). No student ID is used as a
  feature. Prior history enters only through `num_of_prev_attempts`.
- Hyperparameters and the early-stopping validation will use an internal split of the train
  presentations (group-wise by module-presentation), never 2014J.

### 6.5 Demographic attributes. **Decision (confirmed by the author): exclude protected attributes**
`gender`, `disability`, `age_band`, `imd_band` and `region` are known at enrolment. They would be temporally
valid. However, an educator-facing recommendation citing these attributes as SHAP "risk factors" is
ethically problematic, and it is not actionable. Proposal: the model uses behavioural/academic
features plus `num_of_prev_attempts`, `studied_credits`, `highest_education` and `date_registration`.
No demographic-inclusive variant is trained.

### 6.6 Other data-quality notes
- 93 Withdrawn with no unregistration date and 9 Fail with one: kept, documented.
- `score` is missing for 173 TMA submissions. Such a row counts as a submission, but its score is excluded from averages.
- Banked submissions (date −1): the score comes from a *previous presentation* of the same module. We treat them as
  prior information, but **we exclude them from "submitted in this presentation" counts**.

## 7. Candidate features (all computed from events with day < 28)

VLE: total clicks, active days, distinct materials, clicks by main activity type (oucontent,
forumng, quiz, resource/url, homepage), pre-course clicks (day < 0), clicks in week 4 (recent),
activity trend (weeks 3–4 vs. weeks 1–2), days since last activity (at the cutoff).
Assessments: assessments due before the cutoff, submissions before the cutoff, submission rate (due ones),
mean score of submitted assessments, late submissions, banked flag.
Registration/academic: days registered before the start, num_of_prev_attempts, studied_credits,
highest_education.
Excluded: `date_unregistration`, `final_result`, any event with day ≥ 28, exam results, and
`vle.week_from/week_to`.
